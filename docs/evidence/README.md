# 复现证据（I5 最小浏览器闭环）

这个目录回答评审唯一需要机器核验的问题：**在我说的那个提交上，一条完整的链能不能跑起来。**

一条链 = 教师说一句需求 → 流式生成卷子 → 保存并发布 → 学生扫短链在手机上填 → 判分 → 教师看板看见这条提交。

## 两种证据，不要混用

| 证据 | 在哪 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `node scripts/verify.mjs`（VC1–VC16） | 本仓库，随时可跑 | 在没有浏览器的情况下，HTTP 语义层面的闭环成立：快照隔离、版本冲突拒绝、学生端零泄漏、生成→发布→提交→看板的数据一致、简答待批与教师批改后的终分、逐题正确率的分母与零提交口径、缺槽位追问与补答在事件流里的落点、蓝图自洽与 plan 阶段只在有蓝图时出现、覆盖矩阵实际计数与空单元格、收集页问卷的回收统计与 CSV、答案解析开关的默认关闭与开启后回看、单题建议只落在目标题且答案改动进新版本、历史提交仍按自己的快照判分、通用 JSON Patch 越界不写库且撤销后可按 LIFO 重做、补题按知识点×层级回候选且不写库、AI 辅助评分默认关闭且只回建议不落分 | 不能证明界面能用、按钮点了有反应 |
| `node scripts/browser-closed-loop.mjs` | 本仓库，需要本机 Chrome | 真浏览器里点完这条链，每一步的截图落盘 | 不能证明别的机器环境一致；它依赖 `LLM_MODE=mock` 的确定性 |

`verify.mjs` 里跑的是**服务端真逻辑**（真 SQLite、真 HTTP、真判分），不是打桩。
`browser-closed-loop.mjs` 里生成步骤强制 `LLM_MODE=mock`：mock 是内置脚本 + 一条故意写坏再修复的题，
**不调用任何模型**。这样截图每次一致，但也就意味着——它证明的是"链路通电"，不是"模型答得好"。
需要后者时看 `fixtures/replays/` 的三条回放（`LLM_MODE=replay`，同样不调模型）与《计划 v3.0》§7 的 live 说明。

从 R-08 起，浏览器脚本会先构建 `web/dist`，再用 `NODE_ENV=production` 的同源 Node 服务托管页面与 `/assets/*`；启动浏览器前先断言首页响应头含 `script-src 'self'`、`style-src-attr 'unsafe-inline'`，且没有 `script-src 'unsafe-inline'`。开发期 Vite 不使用这条严格 CSP。

## 怎么跑

```bash
pnpm install                      # 一次性
node scripts/verify.mjs           # 期望：VC1..VC16 全部通过，exit 0
node scripts/browser-closed-loop.mjs   # 期望：每步截图进本目录 + stdout 打 JSON 摘要
```

`browser-closed-loop.mjs` 用 `CHROME_PATH` 指定浏览器；未设置时按 Windows 常见路径探测，
找不到会 `exit 2` 并列出找过的路径（不猜、不静默跳过截图）。

## 证据与版本对应

截图文件名前缀是步骤序号，同一次运行内连号。**每次改动可观察行为后必须重跑并覆盖截图**，
旧截图不与新代码混放；`README.md` 末尾的「最近一次运行」必须与 `git log -1` 对得上，
对不上就是证据过期（《计划 v3.0》§8 风险表第 1 条）。

第 2 步是 R-06 的界面级证据：蓝图卡上的题量/题型/分值来自 `/api/plan` 的**结构化返回**（不是前端拼的），
点「按蓝图生成」后时间线才出现 `plan` 阶段与「蓝图对照」那行。

第 9 步是 R-05 的界面级证据：追问条数由服务端判出（不是前端写死的三连问），
「跳过，直接生成」真的能出流——澄清是帮忙，不是关卡。

第 10 步是 R-09 的界面级证据：在生成页**选「问卷」**后，时间线出现「判定为 问卷」
（kind 真的传到了生成链路），问卷字段不带答案/分值；发布后手机视口填写、成功卡片
只有「已提交」；教师看板是「回收情况」逐字段表与「回收记录」，**不出现平均分、
满分或 `0 / 0`**，逐字段行下方列出各选项分布（脚本断言量表「4」这一档为
`count=1`、占比 `100%`），CSV 里能查到刚提交的答案。`verify.mjs` 的 VC11 用两份
提交（量表 4 分与 2 分）核对同一份分布口径：选中档 `rate=0.5`、未选档 `count=0`。
两者分工与前面各步一致。

第 11 步是 A-17（打印版考卷）的界面级证据：卷面题号只数题目、默认不含答案，

下界面外壳（`.no-print`）`display` 为 `none`；`Page.printToPDF` 落盘
`16-print-sheet.pdf`——这份 PDF 是可以直接打开、直接印的成品，不是"看起来像"。

第 12 步是 A-18（提交后答案解析）的界面级证据：教师在看板上点开开关（提示变

「正确」与正确答案、简答题显示「待老师批改」。VC12 验的是同一开关的 HTTP 语义
（默认关闭、开启后 `review`、公开视图不变），两者分工一致。

第 13 步是 A-19（暗色模式）的界面级证据：`Emulation.setEmulatedMedia` 切系统深色后
页面自动进入深色（实测 `body` 底色 `rgb(20, 19, 15)`）；点主题开关按
跟随系统 → 浅色 → 深色 → 跟随系统循环，浅色底色实测 `rgb(247, 247, 245)`。

第 14 步是 A-02「先看蓝图」开关的界面级证据：开关默认开（两阶段是主路径）；
关掉后点「生成表单」直接出字段流，**不出现蓝图卡**，时间线也不出现 `plan` 与
「蓝图对照：」（只发真实事件）。

第 15 步是 A-20（单题精细修改）的界面级证据：在题目列表点第 2 题后，右侧面板
直接改正确选项，底部 diff 只出现「第 2 题 · 答案」这一条；保存生成新版本后，脚本
从详情接口取回整份 Schema，断言**其余题目逐字节不变**、目标题答案确实换成了新选项。

第 16 步是 A-22（覆盖矩阵点击补题）的界面级证据：从看板的矩阵格进入编辑页，

第 7 步（教师批改）是 R-02 的界面级证据：`verify.mjs` 的 VC5 验的是 HTTP 语义，
这里验的是「教师点得到按钮、看得到学生原文、批完看板自己变了」。少这一步，

内置脚本（改第一题题干 + 第 2 题加分），所以这一步证明的是「建议被采用并落成 v2」，
**不是**「模型读懂了那句话」。后者要 `LLM_MODE=live` 才有，见 `docs/evidence/video-script.md` §3。

**2026-10-27 23:38 那轮的改动**：
1. mock 脚本的简答从「无分值」改成 5 分（R-01）：没有这道带分值的简答，
   闭环永远走不到「待批改」那一态，第 7 步也就无从点起。
2. 需求文本里的「共 20 分」跟着改成「共 25 分」——它是从需求文本派生的标题，
   留着 20 会出现「共 20 分 · 满分 25」的自相矛盾。

那一轮还抓到一个真实缺陷（记在 P07 留痕里）：`web/src/publish/build-draft.ts` 的
`toWireItem` 把简答的 `score` 丢掉、`scoreOf` 又对简答返回 0，于是前端发出去的表单
总分比 items 少 5 分。改前改后都能"自洽"，只有学生对不上账——正是浏览器闭环
（学生页显示 20/20，而服务端判分按 25）把它照出来的。

## 这份证据还差什么（诚实口径）

1. **版本冲突只有 HTTP 级证据（VC2/VC6），没有浏览器级证据。** `PATCH /api/forms/:id` 与
   `baseVersionId` 乐观锁已由 R-03 落地，VC6 也证明了旧基线会 409；但**编辑器里的 409 分支**
   仍只有实现与静态检查——要真点击，得先制造一份过期的基线再在界面上点「采用」。
   学生页的冲突分支（`fill-conflict`）有单测。这一段缺的是真点击，不是接口。
2. **生成步骤强制 `LLM_MODE=mock`。** 它证明链路通电，不证明模型产出质量；后者属于 §7 的 live 说明与
   I6 的 `pnpm eval`（整份需求达标率）。
3. **只在 Windows + Chrome 156 验证过。** 换浏览器/系统需要重跑一遍再改这一栏，否则视为证据过期。

这次运行抓到的真实缺陷：单选（`radio`）选不亮——`web/src/fill/StudentField.tsx` 用只认数组的
`selectedValues()` 算选中态，而单选在状态里存的是字符串，于是"点得动、存得下、界面上不亮"。
I4 的验收只看"能否提交、有无泄漏"，没看选中态，所以漏到这一步；修法与回归测试见 `f63613d`。
按纪律，它属于 I4 的缺陷在 I5 被闭环脚本抓到，叙事上写到这里，**不补造修复当时的那次会话**。
