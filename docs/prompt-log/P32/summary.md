## 开工前写清的四件事（纪律 4.0 第 1 条）

| 项 | 内容 |
|---|---|
| 目标 | 负责人的原始反馈：「点击删除会一直卡在删除中」 |
| 取舍 | 不改成弹窗、不改删除接口。根因在 React 复用：删除当前表单后父级自动选中下一份，`DeleteFormAction` 在树里同一个位置被复用，`busy` 状态原样留给新表单。修法是 `key={form.id}` 强制按表单重建，并在成功回调里主动收掉 `busy/confirming` 作为第二道保险 |
| 验收案例 | ①删除当前表单后，下一份表单的按钮立即是「删除表单」，不出现「删除中…」或确认态；②取消仍回到未确认态；③删除后学生短链 404、列表不再出现该表单；④`pnpm check` 与闭环 20 步全绿 |
| 停止条件 | 用刷新页面绕过状态残留；去掉二次确认；把删除成功回调改成延时定时器；改动服务端删除语义 |

## 实现要点

| 层 | 落点 | 关键决定 |
|---|---|---|
| 看板 | `DashboardPage.tsx` | `<DeleteFormAction key={form.id} …>`：key 跟着表单走；成功时先 `setBusy(false); setConfirming(false);` 再 `onDeleted(formId)` |
| 回归 | `scripts/browser-closed-loop.mjs` | 第 20 步删除后额外断言：`dash-delete` 的文本必须是「删除表单」，且 `dash-delete-confirm` 不存在 |

## 我如何引导 AI 修复 Bug

1. **用自己的证据截图定位**。P31 的 `34-deleted.png` 里已经能看到下一份表单的按钮是
   「删除中… / 取消」——闭环只断言了「问卷标题消失」和「学生短链 404」，没有断言删除
   控件自身的状态，所以漏过去了。先复看截图确认现象，再去读 `onDeleted` 的父级逻辑：
   过滤列表后 `pickInitialForm` 自动选中下一份，`FormHero` 仍在原地渲染。
2. **根因不是接口挂起**。`api.deleteForm` 的 Promise 已经 resolve，`onDeleted` 也执行了；
   卡住的是新表单复用了旧组件的 `busy=true`。React 按位置协调，`DeleteFormAction` 没有
   `key`，所以状态跨表单保留。
3. **修法加回归**。`key={form.id}` 是正确修法；成功回调里的重置是防御性第二道保险。
   闭环新增断言，确保以后谁把 key 去掉都会立刻变红，而不是靠人看截图。
