- 提交边界：空白归一化与答案渲染、闭环回归、文档随后分三条提交

## 开工前写清的四件事（纪律 4.0 第 1 条）

| 项 | 内容 |
|---|---|
| 目标 | 朋友本地部署后反馈：填空题显示「第 12/14 项校验未通过：E_LATEX_INVALID」，但题面看起来只是普通填空；另一张截图里填空答案的 LaTeX 没有渲染，直接显示 `$-F'(s)$` / `-\frac{d}{ds}F(s)` |
| 取舍 | 不关闭 LaTeX 校验，也不把填空整题降级成纯文本。根因是模型把整段算式包进 `$...$`，空位写成 `___`，而 KaTeX 把 `_` 当下标起点。修法是**归一化空白**：两个及以上连续下划线变成 `\underline{\hspace{…}}`，校验、页面、Word 共用；单个 `_` 仍是合法下标。答案侧逐项走 `MathText`，不带 `$` 但含 LaTeX 命令的自动补定界符 |
| 验收案例 | ①`$72-___=45+18$`、`$36+___=52-___$` 校验通过；②页面与打印卷把空位渲染成横线，不再是 `___` 源码或红色错误码；③Word 导出的 OMML 也不退回 `___`；④填空答案 `$-F'(s)$` 与 `-\frac{d}{ds}F(s)` 都渲染，纯文本答案（`9`、`H2O`）不变；⑤`pnpm check`、`verify.mjs`、闭环 20 步全绿 |
| 停止条件 | 把 R7 整个关掉；把所有下划线都替换掉（会破坏 `a_1` 这类下标）；把填空答案一律当公式（中文/化学式答案会被 KaTeX 改字体）；只在 UI 层吞掉错误码而不修校验 |

## 实现要点

| 层 | 落点 | 关键决定 |
|---|---|---|
| 空白归一化 | `packages/schema/src/latex.ts` | `normalizeMathBlanks(tex)` 只匹配 `_{2,}`，宽度随下划线个数增长（1–6em 封顶）；`checkLatex` 先用归一化后的公式交给 KaTeX |
| 页面渲染 | `web/src/render/katex.ts` | `renderMathToHtml` 同样先归一化，避免「校验通过但显示仍降级」；失败降级仍保留原始 TeX |
| Word | `web/src/print/docx.ts` | `latexToOmml` 归一化后再取 MathML，保证 Word 里也是空白横线而不是 `___` 源码 |
| 填空答案 | `web/src/render/FieldRegistry.tsx` | 每个答案接 `MathText`；`FillAnswerValue` 对「不含 `$` 且含 `\命令`」的裸 LaTeX 补一对 `$`，纯文本不动 |
| 回归素材 | `packages/llm/src/sources.ts` | mock 填空题干改为 `$12-___=7$`，答案 `5`，让闭环每次都经过这条路径 |
| 闭环 | `scripts/browser-closed-loop.mjs` | 第 6 步逐题表首格断言无 `$`、无 `___`；第 11 步只检查题干段落（卷头姓名线本来就是下划线，不能误伤） |

## 我如何引导 AI 修复 Bug

1. **先看错误码，再复现**。用 KaTeX 直接跑 `72-___=45+18`，确认报
   `Expected group after '_'`；再用 `validateForm` 构造同形表单，稳定复现
   `E_LATEX_INVALID@items[0].title`。这说明不是前端误标，而是校验器把填空空位当成了坏公式。
2. **区分「误报」与「真坏公式」**。`\broken{x}` 仍应报错；只有连续下划线这种
   **填空语义**要放行。归一化只碰 `_{2,}`，单个下标 `a_1` 不动，避免了「一刀切把数学
   都改成文本」的过度修复。
3. **显示与校验同源**。第一版只改了 `checkLatex`，页面仍会在 `MathSpan` 里渲染失败、
   降级成 `<code>`；把同一个 `normalizeMathBlanks` 接到 `renderMathToHtml` 与 Word 转换后，
   三条路径才一致。否则会出现「徽标没了，题面还是源码」的假修复。
4. **答案解析也要看来源**。朋友截图里的答案有 `$-F'(s)$`、`-\frac{d}{ds}F(s)` 两种写法：
   前者是 MathText 能处理的，后者是模型漏了定界符。逐项渲染 + 裸 LaTeX 检测覆盖两种；
   纯文本答案保持原样，不把 `H2O` 拖进公式字体。
5. **闭环断言要避开卷头**。第一次加「打印卷面无 `___`」时被卷头「姓名 __________」
   误伤；改成只扫 `.print-question` 的题干段落。这也提醒：界面上的下划线不一定都是填空空位。

自己否决的：

- **把 `E_LATEX_INVALID` 从错误码表里删掉**：会放过真正的坏公式。
- **全局把所有 `_` 替换成空白**：`a_1`、`x_{n+1}` 会被破坏。
- **把填空答案整体包进 `$...$`**：化学式、中文答案会被当成公式排版，反而更难读。
- **只在预览里把错误徽标隐藏**：校验器仍会拦发布，问题只是从眼前挪到发布按钮。

**已知边界**：

- 只归一化**连续两个及以上**下划线；单个下划线仍按 LaTeX 下标处理。
- 裸 LaTeX 自动补定界符只认「含 `\命令` 且不含 `$`」的答案；`x^2` 这种没有反斜杠的
  写法仍按纯文本显示（不会被误判成公式）。
- 这只是显示与校验层的修复，不改变模型输出；模型仍可能写出其他坏公式，R7 继续拦截。
- 朋友需要重新构建前端/重启服务后再验证，旧构建里的校验器不会自动变。
