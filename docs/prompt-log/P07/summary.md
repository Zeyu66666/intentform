# P07 留痕：简答带分值 + 教师人工批改（省赛 R-01 / R-02）

> 说明：本文件按「提问 → AI 建议（含被否决） → 本人纠正 → 结果与证据」四段整理。
> 引用的自治提示词见同目录 `raw-20261027-p07-short-score.md`。
> 纪律：不补造会话，只记录这一轮真实发生的事；被否决的建议也照实写，因为它们是"人做判断"的证据。

## 一、这一轮的起点

`pnpm eval` 在 I6 跑出整份达标率 42.9%（12/28）之后，失败清单里最扎眼的不是模型答得差，
而是 **15 条需求的结构凑不出来**：需求写「单选 3 道、填空 2 道、简答 1 道，共 20 分」，
而 `short` 字段在 schema 上根本没有 `score`——模型只能给四种客观题分摊分值，
一经 R6 校验就总分不符被打回。也就是说，这部分失败是**产品缺字段**，不是模型能力问题。

本人决定（原话）：「修吧 我已经提交了预制导了 接下来代码都是向省赛靠了」。

## 二、AI 建议，以及当场被否决的

| # | AI 的建议 | 处置 | 否决/采纳的理由 |
|---|---|---|---|
| 1 | 让 `short` 直接进 `isScoredItem`，和四种客观题一样算 `score` | **否决** | 简答没有标准答案可比，进自动判分集合等于"简答恒得 0 分"或"必对"，两种都是假分 |
| 2 | 满分只算四种自动判分题，简答分值到处 `+5` 手写 | **否决** | 「五处各写一遍」正是这个 bug 的成因；手写偏移量下次改分值必漏 |
| 3 | 简答分值不计入 `meta.totalScore`，另开 `maxAutoScore` | **否决** | 学生会看到 20/20 而教师声称 25 分；满分必须是全卷满分 |
| 4 | 批改用 `PUT /grades` 覆盖整个批改集合 | **否决** | 并发下两个教师同批会互相抹掉；改成 `POST` + (提交, 题目) 单条覆盖写，天然幂等 |
| 5 | 批改分累加（每次 `+=`） | **否决** | 教师改分数会越改越高；覆盖写才对，`verify.mjs` VC5 用「批 4 再批 2 → 22 分而不是 27」钉住 |
| 6 | 未批的简答按 0 分算进 `score` | **否决** | 学生看到自己"答了却 0 分"；改成 `pendingScore` 显式说"其中 N 分待人工批改" |
| 7 | 新增 `schemaVersion: 3` | **否决** | 只是字段可选放开，没有破坏性结构变化；升版本会让已有 fixture 与回放键全部失效 |

## 三、本人纠正与真实缺陷

1. **口径统一**：本人要求「带分值 ≠ 自动判分」写进代码注释，而不是只写在文档里——
   于是 `grading.ts` 里 `isScoredItem`（自动判分四种）与 `hasScore`（含简答）**刻意分成两个函数**，
   注释写明"两个集合刻意分开"。
2. **第三处口径（真 bug，靠浏览器闭环照出来）**：`web/src/publish/build-draft.ts` 的 `toWireItem`
   在 `short` 分支把 `score` 丢掉了，`scoreOf` 又对简答返回 0。前后端各自"自洽"，
   于是学生页显示 `20 / 20`、服务端按 `20 / 25` 判——学生对不上账。
   定位方式是跑浏览器闭环：学生页只有 20 分，而 mock 简答明明 5 分。
   修法见 `7bf0dbe`，并补三条测试钉住「简答分值必须进 `totalScore` 也必须进请求体、问卷不许带」。
3. **措辞缺陷**：看板对"没有简答题的表"也逐行显示「已批完」，等于告诉教师"这里有东西要批、已经批完了"。
   改成先判这张表有没有需要人工批改的题（`hasManualItems`），没有就不显示。
4. **证据缺陷**：mock 脚本的简答原本没有分值，闭环永远走不到「待批改」态——
   所以第 7 步（教师批改）根本无从点起。补分值后需求文本里的「共 20 分」也要改成 25，
   否则截图出现「共 20 分 · 满分 25」的自相矛盾。

## 五、偏离与缺口

| 项 | 状态 | 说明 |
|---|---|---|
| 批改的操作留痕（谁批的、何时批的） | 未做 | 表里只存 `score`/`graded_at`，没有 `graded_by` 的教学审计链 |
| 批改的撤销 | 未做 | 覆盖写能改分，但没有"撤销上一次批改"的显式操作 |
| 简答的参考答案与评分要点 | 未做 | 教师看得到学生原文与满分，看不到"该给几分"的提示 |
| 人工批改的量化 | 未做 | `pnpm eval` 不覆盖批改路径；批改目前只有 VC5 与第 7 步两条证据 |
| 版本冲突的浏览器级证据 | 仍未补 | 依赖 R-03 的 Patch |

**诚实口径**：R-01/R-02 让"简答算不算分"这件事在代码里只有一个答案，
但这不代表简答能被自动评分——它只是从"结构上凑不出总分"变成"结构上凑得出、分数等人给"。
这一轮的收益是**解除 15 条需求的结构性失败**，不是模型答得更好；后者要等评估重跑才知道。
