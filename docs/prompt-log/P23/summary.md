## 开工前写清的四件事（纪律 4.0 第 1 条）

| 项 | 内容 |
|---|---|
| 目标 | 负责人要出一张高三试卷，含很多知识点，想指定「立体几何 1 道单选 + 1 道简答」。现有蓝图只有题型总分布与知识点清单，两者没有「谁配谁」的关系，模型可能把立体几何全放进选择题 |
| 取舍 | 采用**部分配额**：每条 `{知识点, 题型, 题量}` 只钉住指定组合，其余题仍按 `typeMix` 自由分配；不要求每题都归入知识点，旧蓝图继续合法 |
| 验收案例 | ①蓝图卡能加两条「立体几何 · 简答 1」「立体几何 · 单选 1」；②删除知识点连带删配额；③题型总数调小后配额被裁剪且蓝图仍可确认；④配额未兑现时蓝图对照列出差异；⑤`pnpm check`、VC1–VC17、十八步闭环全绿 |
| 停止条件 | 需要改 `plan.v1` / `generate.v3` 提示词正文、重录 fixture、把配额做成整表门禁、或要求每道题必须归入知识点 |

## 我如何引导 AI 修复问题

本轮抓到的真实问题：

1. **`exactOptionalPropertyTypes` 拒绝 Zod 的可选字段**。`quotas` 在解析结果里的类型是 `readonly BlueprintQuota[] | undefined`，直接赋给 `quotas?: readonly BlueprintQuota[]` 编译失败。把接口显式写成 `?: readonly BlueprintQuota[] | undefined`，而不是用 `as` 糊过去。
2. **`addQuota` 最初写成「同一知识点只能有一条」**。这会直接挡住负责人要的「立体几何同时出单选和简答」。改为按 `(知识点, 题型)` 判重，同一知识点可以有多种题型。
3. **改知识点/题型会制造重复组合**。`withQuotaKnowledgePoint` / `withQuotaType` 只检查容量，没检查目标组合是否已被另一行占用；补了会失败的测试，再用 `quotaPairFree` 统一判重，界面也禁用会重复的选项。
4. **浏览器 mock 蓝图没有知识点**。为了让闭环覆盖真实编辑路径，测试先手动加知识点并改名「立体几何」，加两条配额并断言，截图后删除知识点，再验证配额行一起消失；这样既不污染后续生成，也证明级联删除。

自己否决的：

- **矩阵式全量分配（每个知识点 × 每种题型都填）**：在 300px 左栏里过宽，且会强迫教师给每道题归类；配额列表更贴近「我只想钉住这两道」的用法。
- **把配额做成整表门禁**：模型不遵守就发布失败，会把结构偏差升级成无法交付；本轮只记录偏差，由教师决定是否重生成。
- **升提示词版本并重录三条录像**：没有真实上游额度可重录，拿旧录像冒充新提示词违反仓库纪律；本轮不改提示词正文。
