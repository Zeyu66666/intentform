## 开工前写清的四件事（纪律 4.0 第 1 条）

| 项 | 内容 |
|---|---|
| 目标 | 负责人新建高三试卷，在蓝图里指定「解析几何 · 简答 · 1」；生成后第 15 题是一道填空题，却出现在「四、解答题」分节下。分节题量也对不上：填空题只有 2 道（蓝图 3 道）、解答题有 6 道（蓝图 5 道） |
| 取舍 | 不把分节升级成硬门禁（生成失败会让教师无从改起），而是两头做：①提示词把「每个 section 恰好 count 道题、标题写明题型时不许混入」和 `quotas` 写成硬约束；②`compareWithBlueprint` 增加分节题量与分节题型两项对账，时间线点名到题（「解答题里的 q14 是填空，该节应为简答」）。同时补上 `knowledgePoint` 必须是 id 的规则——无蓝图生成时模型会写中文名称，直接触发逐行校验失败 |
| 验收案例 | ①分节标题写了「解答题」却混入填空题 → `sectionTypeMismatches` 非空且 `isExact=false`；②分节题量与蓝图对不上 → `sectionMismatches` 列出计划/实际；③真实 Key 生成一份 16 题 / 150 分的卷子，选择 8 / 填空 4 / 解答 4 逐节兑现，解析几何简答配额命中；④`pnpm check`、`verify.mjs`、`check-fixtures` 全绿；⑤旧 v5/v6 生成录像删除并按 v7 重录 |
| 停止条件 | 把分节偏差做成硬失败（教师拿不到可编辑的卷子）、只改提示词而不做任何结构对账、或保留「配额里写中文知识点名也能过」的口径 |

## 实现要点

| 层 | 落点 | 关键决定 |
|---|---|---|
| 提示词 | `packages/llm/src/prompt.ts` | `generate.v6`：分节必须逐节兑现，标题写明题型时不许混入（填空题不许放进解答题）；`quotas` 必须命中知识点 id + 题型。`generate.v7`：`knowledgePoint` 必须是小写 id，不能写中文名称 |
| 对账 | `packages/schema/src/blueprint.ts` | `sectionMismatches` 按顺序比较每个分节的计划/实际题量；`sectionTypeMismatches` 从标题识别题型（单选/多选/填空/解答/数值/量表），列出混入的题；两项都进 `isExact` |
| 时间线 | `packages/llm/src/generate.ts` | 摘要不再只说「有偏差」，而是列出分节题量、混入题型与配额差异，点名到题 id |
| 验证脚本 | `scripts/verify.mjs` | VC13 的题号断言改为「只数题目、不数分节」，与 P25 的编辑器口径一致 |

## 我如何引导 AI 修复问题

本轮抓到的真实问题：

1. **分节结构完全没人核**。模型把一道解析几何填空题放进「四、解答题」，总数、总分、题型分布全对，`compareWithBlueprint` 因此判 `isExact=true`。修法是把「分节按位置、按标题题型」两类对账加进纯函数，并用真实表单复算：填空题计划 3 实际 2、解答题计划 5 实际 6，`q14` 被判为混入的填空。
2. **`quotas` 根本没进生成提示词**。蓝图 JSON 里有配额，但系统提示只写「题量、题型分布、难度分布、总分、章节与知识点」，模型没有理由兑现。补成硬约束后，真实 Key 的 16 题卷子命中「解析几何 · 简答 · 1」。
3. **v6 录像的原始行不合法**。第一次重录数学卷时模型把 `knowledgePoint` 写成「开口方向」「顶点坐标」，8 行全部触发 `E_KP_UNKNOWN`/`E_SCHEMA_SHAPE`，fixture 自检拒绝入库。没有放宽校验，也没有改 fixture 内容；补 `generate.v7` 的 id 规则后重录，三条生成录像 0 行失败。
4. **VC13 被我自己的题号口径改红**。`verify.mjs` 仍按 Schema 下标断言「第 2 题」，与 P25 的新口径冲突；改成按非分节节点数计算题号，验证回到 17/17。
5. **旧录像残留导致 fixture 数量超限**。重录后目录里同时有 v5、v6、v7 三套生成录像，`check-fixtures` 报「9 超过 6」。删掉旧的两套，只保留当前版本的 3 条生成 + 3 条蓝图。

自己否决的：

- **把分节偏差做成发布失败**：教师需要拿到半成品继续编辑；对账 + 时间线点名比整份拒收更可用。
- **在服务端自动把填空题挪回填空题分节**：标题与题型的对应关系是启发式，自动挪动可能把有意的混排改坏；只报告，不替教师做结构决定。
- **保留中文知识点名并放宽 id 校验**：会让 `knowledgePoint` 与蓝图 id 脱钩，配额与覆盖矩阵全部失效。
- **只重录有问题的数学录像**：回放键按需求分文件，但版本号进键；升版后三条生成录像必须全部换新，否则旧键配新版本会被 `fixtures.test.ts` 判红。

**已知边界**：

- 分节题型识别基于中文标题关键词（单选/多选/填空/解答/数值/量表）。标题写成「综合题」「第二部分」这类不含题型词的分节不参与题型对账，只参与题量对账。
- 对账是**报告**不是门禁：模型仍可能不兑现，教师会在时间线看到偏差并在编辑器里调整。
- 负责人当前运行的开发服务若未重启，仍会使用旧的 `generate.v4` 提示词与旧代码；本轮改动需要重启服务后生效。
