## 我如何引导 AI 修复问题

本轮抓到的真实问题：

1. **底部改动条被挤出视口**。第一次截图里 1280×800 的页面只能看到编辑面板，保存按钮在屏幕外。根因是 `RouteView` 的 `min-h-screen` 只保证「至少一屏」，内容变高时 `h-full` 的编辑器跟着长，`shrink-0` 的底栏被推到下面。改成只在编辑路由使用 `h-dvh`，让中栏成为唯一滚动区。
2. **第一道题显示成「第 2 题」**。截图里左栏第一项是分节，紧跟的单选题写着「第 2 题」，而整份卷子没有「第 1 题」。根因是 `whereOf` 与编辑器都用 Schema 下标 +1，分节也占了一个号。修法是把「题号 = 非分节节点的序号」写进 `packages/schema/src/patch.ts`，并让编辑器、diff、单题建议、闭环断言共用这一口径；分节本身用标题定位。
3. **分组卡片里出现了「分节 · 分节」**。左栏对分节同时渲染了「分节」徽标和类型标签，读起来像重复。改成分节只显示徽标 + 标题，题目才显示「第 N 题 · 题型」。
4. **JSX 三元表达式少一个右括号**。`{condition ? null : (<Group/>)}` 写成了 `) : null}`，`tsc` 直接报 TS1005；按报错行修正，没有靠猜改结构。
5. **改题号口径后服务端与闭环测试变红**。`server/src/forms-route.test.ts`、`suggest-route.test.ts`、`web/src/edit/patch-plan.test.ts` 中「下标 1 = 第 2 题」的旧断言与新口径冲突；逐处改成「按非分节节点数题号」，并新增 `patch.test.ts` 用例钉住分节不占号。闭环脚本的 `expectedWhere` 与「仅第 X 题」同步改为计算值，而不是换一个硬编码数字。

自己否决的：

- **引入富文本编辑器**：会破坏「公式原文可编辑」与现有 `formSchema` 校验链路，还要引入依赖；KaTeX 预览已经能让教师边改边看。
- **加一套新配色或阴影体系**：项目只有 6 个颜色 token，编辑器的层次靠分组、间距、边框与强调色完成，不扩充调色板。
- **只在列表里改题号**：diff 与建议条仍会显示旧题号，教师会以为是两道不同的题；口径必须一次改到底。
- **把编辑页改成文档滚动**：底栏会重新跑出视口；`h-dvh` 只作用于编辑路由，影响面最小。

- 题干与解析仍是 `textarea` 里的公式原文；预览能看渲染效果，但**不能在预览里直接编辑**（富文本编辑器不在本轮范围）。
