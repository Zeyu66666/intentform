## 开工前写清的四件事（纪律 4.0 第 1 条）

| 项 | 内容 |
|---|---|
| 目标 | 负责人的原始诉求：「接下来改教师看板 ui」。此前看板是「下拉框 + 一列表格」：表单身份、学生链接、两个开关、四张统计表挤在同一列里，教师打开后第一眼看到的是开关而不是班级数据；提交数、平均分、满分只是表格上方的一行 `<dl>`，扫读成本高 |
| 取舍 | 版面按「表单身份 → 关键数字 → 明细 → 设置」重排：顶部表单卡集中切换器、状态、学生链接与编辑/打印入口；四张数字卡回答「交了多少 / 均分多少 / 卷面多少 / 还要批多少」；正确率、提交记录、覆盖矩阵各自成卡；设置项降到数据之后。**不新增颜色、不引入图表库**，条形仍是 CSS；所有 `data-testid` 与「`—` 不是 0」的口径原样保留；问卷不出现均分/满分 |
| 验收案例 | ①看板首屏能看到表单名、状态与四个关键数字；②切换表单仍走 URL，刷新与后退不丢选中项；③有提交时正确率条、批改按钮、批改面板贴着行显示；④零提交时均分是 `—`、正确率是 `—`；⑤问卷页只有回收份数/字段/版本，不出现「平均分」「满分」与 `0/0`；⑥暗色模式下所有卡片、表头、按钮可读；⑦闭环 19 步、`pnpm check`、`verify.mjs` 全绿 |
| 停止条件 | 为「好看」新增第 7 个颜色或图表依赖、改掉 `data-testid` 与口径文案导致闭环断言失效、把问卷也塞进均分/满分卡片、为了排版把「提交数」改成「提交份数」这类同义改写（闭环按字面断言）、或让设置开关默认收起导致教师找不到 |

## 实现要点

| 层 | 落点 | 关键决定 |
|---|---|---|
| 页面骨架 | `DashboardPage.tsx` | `max-w-6xl` 与顶栏对齐；页头「教学数据 / 教师看板」+ 刷新与生成入口；表单卡、数字卡、表卡统一用 `border-line + bg-surface`，表头用 `bg-bg`，行 hover 用 `bg-bg` |
| 表单身份 | `FormHero` | 切换器放在表单卡顶部（它换的是整张卡）；状态/类型用双色 chip：已发布用 `success`，草稿用 `muted`；学生链接保留完整 `/f/<slug>`，未发布时给「去编辑器发布」 |
| 关键数字 | `StatsGrid` / `StatCard` | 判分测验四卡：提交数、平均分、满分、待批改（`rows.filter(needsGrading).length`）；问卷三卡：提交数、可回收字段、当前版本，**不渲染均分/满分** |
| 明细表 | `ItemStatsCard` / `CollectionCard` / `RecordsCard` | 每题正确率第四格仍只输出百分比文本（CSS 条不带文本），闭环 `cells[3] === "100%"` 继续成立；提交时间拆成日期/时间两行，但得分格保持 `rowScoreText()` 的单串文本；批改面板仍紧贴被点行 |
| 覆盖矩阵 | `CoverageCard` | 仍是 `<details>`，默认收起；`summary` 隐藏原生三角，改用「展开矩阵 / 收起矩阵」文案（`group-open`），点击区域整行可点 |
| 设置 | `SettingsRow` | 从表单卡下方移到数据之后；两个开关改成带说明的卡片，保留「（已开启）/（默认关闭）/（读取中…）」字面量 |
| 批改面板 | `GradeForm.tsx` | 学生原文放进浅底块；AI 建议放进浅底提示块；输入框旁显示 `/ 满分`；保存按钮改主色 |

## 我如何引导 AI 修复问题

本轮抓到的真实问题：

1. **改文案把闭环断言改断了**。第一次跑闭环，第 12 步「答案解析」超时：脚本等的是页面文本里出现 `（已开启）`，而重排设置卡时把它写成了「已开启：学生提交后可查看解析」。这不是测试挑剔——评审按字面复现；恢复带括号的状态词后重跑通过。教训是：**界面文案可能是证据脚本的契约**，改之前先 grep。
2. **均分卡与满分卡互相重复**。第一版均分卡的副标题写「满分 25」，下一张卡就是「满分 25」，等于同一个数字出现两次。用 2000px 高的临时视口截图做整页目检时发现，改成「按全部提交计算」；未知时仍保留「还没有人提交，不是 0 分」。
3. **口径标签不能顺手「优化」**。重排时想把「提交数」改成更准确的「提交份数」，但闭环第 6 步按 `stats.includes("提交数")` 断言；保留原文案。类似的还有每题正确率表必须四列都是 `<td>`、第四格只能有百分比文本。

自己否决的：

- **引入图表库（Recharts 等）**：四张数字卡与 CSS 条已经能回答看板的问题，新增依赖换来的是更大的包和一套新颜色。
- **把看板做成两栏（左数据、右设置）**：提交记录与正确率表需要宽度；设置不是高频操作，放右栏会挤压表格。
- **设置默认收进 `<details>`**：省空间，但教师找不到「提交后展示答案解析」，闭环也得先点开才能操作。
- **把 CSV 移到页头**：导出属于「提交记录」这张表，放在表头语义更近；页头只留生成与刷新。
- **给问卷也凑四张卡**：问卷没有均分与卷面，硬凑只会造出无意义的数字。

**已知边界**：

- 提交记录仍不分页、不排序（服务端契约就是当前发布版本的全部提交）；学生姓名不在数据模型里，看板只能按时间与分数识别。
- 「待批改」卡的数字从已加载的 `rows` 派生，与均分/满分来自服务端 summary 不同源；两者在正常响应下一致，但它是视图派生值，不写回接口。
- 覆盖矩阵仍是进阶信息，默认收起；手机宽度下三张表横向滚动，不折行。
- 学生链接没有「复制」按钮：`navigator.clipboard` 在非安全上下文与部分浏览器里不可用，本轮不引入降级分支。
